P18 [NoStyle]: This project delivers a production-grade Natural Language Processing pipeline that classifies Amazon Echo customer reviews as Positive or Negative sentiment, wrapped in an enterprise engineering layer meeting Step 17 production standards. Across 3,062 cleaned customer reviews (87.7% Positive, 12.3% Negative), a Stratified 5-Fold Cross-Validated, GridSearch-tuned Logistic Regression classifier (C = 10.0, solver = liblinear) was selected as the production model, achieving 92.99% test accuracy and a 96.12% F1-Score on the positive class, validated by a 92.16% mean cross-validation accuracy.
P19 [NoStyle]: Beyond the modelling task, the system was re-engineered with centralized configuration management, structured logging, automated result export, model versioning, a CLI batch-prediction tool, a full unit test suite (10/10 passing), and an optimized multi-page Streamlit dashboard — transforming a coursework notebook into a deployable analytics service.
P20 [NoStyle]: E-commerce platforms accumulate thousands of unstructured customer reviews daily. Manually triaging this volume to identify dissatisfied customers, emerging product defects, or marketing-worthy praise does not scale. This project builds an automated, reproducible sentiment classification pipeline that ingests raw review text, cleans and vectorizes it, benchmarks multiple classifiers under rigorous cross-validation, and serves predictions through both a CLI tool and an interactive web dashboard.

P30 [Heading 2]: 3.1 Review Length Characteristics
P31 [NoStyle]: Review length (word count) is strongly right-skewed for both classes: the majority of reviews — positive and negative alike — fall under 20 words, with a long tail of more detailed reviews extending past 100 words. This informed the choice of a bag-of-words-style TF-IDF representation over sequence-sensitive embeddings, since most signal is carried by short, high-frequency phrases rather than long-range context.

P35 [NoStyle]: Raw review text is passed through a modular cleaning pipeline (utils/preprocess.py) prior to vectorization:
P36 [List Paragraph]: 1. Noise Removal: Lowercasing, HTML tag stripping, URL removal, and regex-based punctuation/number removal.
P37 [List Paragraph]: 2. Negation-Preserving Stopword Filtering: Common stopwords are removed using NLTK's stopword corpus, with an explicit exception list that preserves negation particles and fuses them with the following token (e.g. “not_good”, “never_failed”) so that negated sentiment is not collapsed into its unnegated root word.
P38 [List Paragraph]: 3. Lemmatization: Cleaned tokens are reduced to their dictionary root form using NLTK's WordNet lemmatizer, which was preferred over stemming to avoid producing non-words that hurt interpretability of downstream coefficients.
P39 [Heading 2]: 4.1 Vectorization Choice — TF-IDF
P40 [NoStyle]: Cleaned text is converted into numerical features using Term Frequency–Inverse Document Frequency (TF-IDF) vectorization with max_features capped at 5,000. TF-IDF was selected over a raw Bag-of-Words representation because it down-weights ubiquitous but low-information terms (e.g. “echo”, “device”, which dominate the corpus regardless of sentiment) while up-weighting terms that are more discriminative of a specific review's content. It was preferred over dense embeddings such as Word2Vec for this task because the dataset is short-text and moderate in size, where sparse linear models trained on TF-IDF features are both faster to train and more directly interpretable via coefficient inspection — a requirement of the Model Interpretability section below.
P42 [NoStyle]: Three classical text-classification models were benchmarked, each tuned independently via GridSearchCV over a stratified 5-fold cross-validation split, ensuring the class ratio is preserved across every fold despite the dataset's imbalance:
P43 [List Paragraph]: Logistic Regression: Hyperparameter grid over C (inverse regularization strength), solver, and penalty.
P44 [List Paragraph]: Multinomial Naive Bayes: Hyperparameter grid over alpha (Laplace smoothing).
P45 [List Paragraph]: Linear SVM (Calibrated): Hyperparameter grid over C and loss function, with probability calibration applied for confidence scoring.
P47 [NoStyle]: Logistic Regression was selected as the production model on the strength of its F1-Score and near-perfect positive-class recall, combined with fast training (~7.08s) and directly interpretable coefficients.

P94 [Heading 2]: 10.4 Known Limitation & Mitigation Path
P95 [NoStyle]: Given the 7.1:1 class imbalance, the current model under-detects negative sentiment (49% recall on the minority class). For a production deployment prioritising complaint detection, the recommended next iteration would apply class_weight='balanced' or SMOTE-based oversampling and re-tune the decision threshold to favour negative-class recall, accepting a modest reduction in positive-class precision in exchange for catching more dissatisfied customers.
P97 [Heading 2]: Q1 — Why TF-IDF Over Bag-of-Words or Word2Vec?
P98 [NoStyle]: TF-IDF retains the speed and interpretability of a sparse bag-of-words representation while correcting its main weakness: it down-weights terms that appear in almost every document (like “echo” in this corpus) and up-weights terms that are more discriminative of an individual review. Dense embeddings like Word2Vec were not necessary here because the dataset is short-text and moderate in size, where a linear model over sparse TF-IDF features trains faster and produces directly inspectable coefficients.
P99 [Heading 2]: Q2 — Why Does F1-Score (96.12%) Exceed Accuracy (92.99%)?
P100 [NoStyle]: The reported F1-Score is the Positive-class F1, computed from Positive-class precision (0.93) and recall (0.99). Because Positive reviews make up 87.7% of the data, a metric computed on that single dominant class will naturally sit close to — and can exceed — overall accuracy. The Macro-averaged F1 of 0.80, which weights both classes equally, is the more honest single-number summary of balanced performance.
P101 [Heading 2]: Q3 — Why Is Negative-Class Recall Only 49%?
P102 [NoStyle]: With only 377 negative examples against 2,685 positive ones, the model sees far fewer negative training signals and — combined with the default 0.5 decision threshold — is biased toward predicting the majority class. This is a textbook consequence of class imbalance rather than a modelling error, and is the primary limitation flagged in the roadmap.
P103 [Heading 2]: Q4 — Why Was Logistic Regression Chosen Over SVM or Naive Bayes?
P104 [NoStyle]: All three tuned models scored within roughly 0.3 percentage points of each other on accuracy. Logistic Regression was selected because it achieved the highest F1-Score and near-perfect positive recall, trains in a comparable timeframe, and — critically for this report's interpretability requirement — exposes directly interpretable per-word coefficients without requiring the additional probability-calibration step that Linear SVM needed.
P106 [NoStyle]: This project delivers a fully benchmarked, production-engineered sentiment analysis system: a Logistic Regression classifier tuned via Stratified 5-Fold Cross-Validation and GridSearchCV, evaluated with full diagnostic transparency including confusion matrices and interpretable coefficients, and wrapped in a Step 17-compliant engineering layer of configuration management, logging, versioning, automated testing, CLI tooling, and a cached, batch-capable Streamlit dashboard.
P107 [NoStyle]: BOTTOM LINE   A 92.99% accurate, 96.12% F1 production sentiment engine is ready for deployment, with the clearest next engineering step being class-imbalance correction to lift negative-review detection beyond its current 49% recall — directly increasing the system's value as an early-warning tool for customer dissatisfaction.
